The review API.

This is the API documentation hosted on GitHub Pages. To browse reviews or call these endpoints, run the application locally or use a separately hosted backend.

{% endif %}

Read reviews without a token. Every response is JSON. Public browsing and search never modify records.

Browse and search

GET /api/selectall?limit=50&offset=0
GET /api/searchsome?country=SG&keyword=seaweed&sortby=Brand

Responses contain items, limit, offset, has_more and next_offset. The default page has at most 50 reviews; choose a limit from 1 to 200 and an offset up to 100000. Fetch another page only when needed. Changes between requests can move records between pages.

Filters: ID, Country, Brand, Type, Package and Rating. Names are case-insensitive. keyword searches for literal text within Type; percent signs and underscores are literal characters. sortby accepts a review column. Sorting uses the stored text. Search requires at least one filter; the old PUT search route still accepts form or JSON fields.

Administrative writes

An operator sets RAMEN_ADMIN_TOKEN to a random secret of at least 32 characters on the server. Send it in the Authorization: Bearer <token> header. Keep it out of URLs, browser storage and source control. Writes are unavailable until configured; reads remain available.

MethodEndpointBehavior
POST/api/createoneCreate missing storage without replacing records.
POST / PUT/api/addoneAdd the supplied review fields.
POST/api/addmanyAppend the configured CSV atomically, up to 8 MiB / 10000 rows. Repeating an import appends again.
PUT/api/editsomeRequire a filter and update fields such as updatebrand or updaterating.
DELETE / PUT/api/deletesomeDelete only reviews matching the supplied filters.
DELETE/api/deleteallAlso require X-Confirm-Delete: all-reviews. This removes every review.

Write bodies may be JSON objects or form fields. Requests are limited to 32 KiB and values to 4096 characters. Unknown, duplicate or missing required fields are rejected. The server returns the affected row count and never retries a write automatically. After a lost response, check the result before attempting the write again.

Errors

400: invalid input. 401: missing or invalid token. 404: no matching rows for an edit or filtered deletion. 405: wrong HTTP method. 413: request too large. 503: storage unavailable or administrative writes unconfigured. Database failures are never reported as successful mutations.

Running locally

python -m pip install -r requirements.txt
python main.py

Use Python 3.12. Both main:app and app:app expose the same application. Production hosting needs persistent storage and HTTPS. The GitHub Pages site is documentation; it does not run this API.
